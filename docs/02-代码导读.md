# 02 · 代码导读

> 按执行顺序读。七个模块，每个只解决一个问题。

```
调用方（Agent）
   │  executor.call("charge", {"order_id": "ORD-1001", "amount": 9.9})
   ▼
registry.py ──► 找到 ToolSpec（含 policy：重试/超时/限流/熔断配置）
   │
   ▼
schema.py ──► validate_args() ──失败──► errors.ValidationError（不重试，尝试 0 次）
   │ 成功
   ▼
policy.py ──► TokenBucket.try_acquire() ──失败──► RateLimited（可重试）
   │
   ▼
policy.py ──► CircuitBreaker.allow() ──失败──► CircuitOpen（不重试）
   │
   ▼
executor.py ──► _invoke()（线程池 + 超时）
   │ 异常
   ▼
executor.py ──► _classify() → ToolError(retryable=?) ──► 决定是否退避重试
   │
   ▼
audit.py / metrics.py ──► 每次尝试都记一条
```

## 1. `errors.py` —— 一切的起点

先读这个文件，因为它定义了整个库的语义。

```python
class ToolError(Exception):
    code: str = "tool_error"
    retryable: bool = False     # ← 核心：默认不可重试
```

七个子类各自的 `retryable`：

| 类 | code | retryable | 理由 |
|---|---|---|---|
| `ValidationError` | `validation_error` | `False` | 重试不改变参数 |
| `ToolNotFound` | `tool_not_found` | `False` | 工具不存在，重试还是不存在 |
| `ToolTimeout` | `timeout` | `True` | 可能只是瞬时变慢 |
| `ToolExecutionError` | `execution_error` | `True` | 默认网络类故障 |
| `RateLimited` | `rate_limited` | `True` | 等一会就好 |
| `CircuitOpen` | `circuit_open` | `False` | 熔断器已判断重试无意义 |
| `FatalToolError` | `fatal` | `False` | 鉴权/配置错误 |

**注意 `ToolExecutionError` 默认 `True`，但执行器在遇到 `ValueError`/`TypeError` 这类异常时，
会显式传 `retryable=False` 覆盖它。** 见 `executor.py::_classify`。

## 2. `schema.py` —— 约束要真的执行

### 2.1 `Field`：把约束挂在类型注解上

```python
def charge(order_id: Annotated[str, Field(description="订单号", pattern=r"^ORD-\d{4}$")],
           amount: Annotated[float, Field(description="金额", ge=0.01, le=10000)]) -> dict:
```

`annotation_to_schema()` 会：

1. 从 `__metadata__` 里取出 `Field`；
2. 剥掉 `Annotated` 外壳拿到真实类型；
3. 生成 JSON Schema，并把 `ge/le/min_length/max_length/pattern/enum` 映射成
   `minimum/maximum/minLength/maxLength/pattern/enum`。

### 2.2 `validate_args()`：三层递归校验

```python
def _validate_value(value, schema, path, errors, *, coerce) -> Any
```

递归处理四种结构：

- **标量**：类型检查 → 纠偏 → 再检查 → enum → 数值范围 → 长度 → 正则
- **数组**：对每个元素递归，路径加下标 → `$.nums[1]`
- **对象**：对每个字段递归，路径加点 → `$.profile.age`
- **anyOf**：任一分支通过即可

所有错误收集到列表里**一次性返回**，而不是遇到第一个就抛。
理由：模型一次看到全部问题，比来回修三轮更快。

### 2.3 类型纠偏的底线

```python
def _type_ok(value, wanted) -> bool:
    if wanted == "integer":
        if isinstance(value, bool):
            return False          # ← True 不是整数 1
        ...
```

`test_bool_is_not_integer` 就是防这个的。Python 里 `True == 1`，不显式拦就会静默算错。

## 3. `policy.py` —— 四个策略，都可注入时钟

### 3.1 `RetryPolicy.delay_for()`

```python
raw = min(max_delay, base_delay * multiplier ** (attempt - 1))
if jitter:
    raw *= 1 + source.uniform(-jitter, jitter)
return max(0.0, raw)
```

`rng` 可注入 → 测试里断言精确的退避序列。

### 3.2 `TokenBucket`

```python
def _refill(self):
    elapsed = max(0.0, now - self._updated)
    self._tokens = min(burst, self._tokens + elapsed * rate_per_sec)
```

惰性补充（不是起一个定时器），所以只需要一个 `clock`。
`try_acquire()` 非阻塞，`acquire(timeout)` 阻塞式。

### 3.3 `CircuitBreaker` 状态机

```python
def allow(self) -> bool:
    with self._lock:
        self._maybe_recover()               # OPEN 且超时 → HALF_OPEN
        if self._state is CLOSED: return True
        if self._state is HALF_OPEN:
            if self._half_open_calls < policy.half_open_max_calls:
                self._half_open_calls += 1
                return True
            return False
        return False                        # OPEN
```

`_transition()` 里对每个目标状态做初始化：

```python
if new_state is HALF_OPEN: self._half_open_calls = 0; self._half_open_successes = 0
elif new_state is CLOSED:  self._consecutive_failures = 0
elif new_state is OPEN:    self._opened_at = self._clock()   # ← 重置计时器
```

`self.transitions` 记录每一次状态迁移，既方便测试断言，也方便线上观测
（示例 2 就是直接打印这条轨迹的）。

## 4. `audit.py` —— 入参和返回值都脱敏

```python
def redact(value, *, extra_keys=(), depth=0):
    if depth > 8:
        return "<max-depth>"                       # 防自引用结构炸栈
    if isinstance(value, dict):
        for key, item in value.items():
            if key.lower() in extra or _is_sensitive(key):
                out[key] = MASK
            else:
                out[key] = redact(item, ...)
```

`_is_sensitive()` 用**关键词片段**匹配（`password`、`token`、`手机`、`身份证`…），
所以 `user_password`、`access_token` 这类变体也能命中。

`AuditLog.record()` 里两个关键点：

```python
merged_keys = tuple(self.redact_keys) + tuple(extra_keys)
safe_result = redact(result, extra_keys=merged_keys)     # ← 返回值也要脱敏
text = safe_result if isinstance(safe_result, str) else json.dumps(safe_result, ...)
preview = text[:self.max_preview] + "…"                  # ← 只存预览，不存全文
```

**只存预览**是刻意的：审计日志的目标是"可追溯"，不是备份数据。
存全文会让日志体积失控，还会把大量数据落盘。

## 5. `metrics.py` —— 分位数用线性插值

```python
position = fraction * (len(sorted_values) - 1)
low, high = int(position), min(int(position) + 1, len(...) - 1)
weight = position - low
return values[low] * (1 - weight) + values[high] * weight
```

和 `numpy.percentile` 默认行为一致。`latencies_ms` 用 `deque(maxlen=2000)` 做环形缓冲，
防止长时间运行时内存无限增长。

## 6. `registry.py` —— 装饰器与注册表不打架

尴尬点：版本、标签、废弃标记既可以写在 `@tool(...)` 里，也可以写在 `register(...)` 里。
两处都写就会打架。处理方式是**显式参数 > 装饰器元数据 > 默认值**：

```python
meta = getattr(func, "__tool_meta__", None) or {}
version = version if version is not None else meta.get("version", "1.0.0")
```

（所以这些参数的默认值必须是 `None` 而不是 `"1.0.0"` —— 否则无法区分"没传"和"传了默认值"。
这个 bug 我在写测试时才发现，`test_decorator_metadata_preserved` 现在盯着它。）

另一个设计：**废弃工具默认不下发给模型**。

```python
def schemas(self):
    return [spec.schema() for spec in self.tools.values() if not spec.deprecated]
```

因为工具列表会占用模型的上下文，废弃工具留着只会让模型误用。
需要直接调用时仍然可以（会发 `DeprecationWarning`）。

## 7. `executor.py` —— 主流水线

### 7.1 `call()` 的六个阶段

读这个方法的注释比读代码快，它把每个阶段的错误类型都标了。

### 7.2 重试循环

```python
for attempt in range(1, max_attempts + 1):
    attempts_made = attempt
    try:
        value = self._invoke(spec, cleaned)
    except BaseException as exc:
        error = self._classify(exc, spec)
        ...
        if not error.retryable or attempt >= max_attempts:
            break                       # ← 不可重试 或 次数用尽
        self.metrics.record_retry(tool)
        delay = spec.policy.retry.delay_for(attempt)
        self._sleeper(delay)
```

注意 `except BaseException` 而不是 `except Exception`：
`KeyboardInterrupt` 也会被分类，但 `_classify` 会给它 `retryable=False`，所以不会吞掉。

### 7.3 `_classify()`：异常 → 语义

```python
if isinstance(exc, ToolError):            return exc               # 已经是我们的类型
if isinstance(exc, _RETRYABLE_EXCEPTIONS): return ToolExecutionError(..., retryable=True)
if isinstance(exc, (ValueError, TypeError, KeyError, IndexError,
                    AttributeError, NotImplementedError, AssertionError)):
    return ToolExecutionError(..., retryable=False)                  # 代码写错了
# 未知异常
return ToolExecutionError(..., retryable=spec.policy.idempotent)
```

最后一条的取舍：**未知异常对幂等工具按可重试处理，对非幂等工具按不可重试处理。**
理由是非幂等操作重复执行的风险高于"少重试一次"的收益。

### 7.4 `_invoke()`：超时的实现

```python
future = pool.submit(spec.func, **cleaned)
try:
    return future.result(timeout=timeout)
except FuturesTimeout as exc:
    future.cancel()                     # ← 只在任务未开始时有效
    raise ToolTimeout(...) from exc
```

注释里明确写了：`cancel()` 基本没用，线程会继续跑。这是已知局限，不是疏忽。

### 7.5 `call_many()`：并发对应"一轮多个 tool_calls"

```python
with ThreadPoolExecutor(max_workers=min(len(calls), 8)) as pool:
    futures = [pool.submit(self.call, name, args, correlation_id=cid) for ...]
```

注意**所有子调用共享同一个 `correlation_id`** —— 这样在审计日志里，
模型一轮发出的多个工具调用可以被关联起来分析。

（内部用两套线程池：外层跑并发调用，内层跑单个调用的超时。所以 `max_workers` 要
大于并发数，否则会互相等待。这个约束写在 `__init__` 的注释里。）

## 8. 测试思路（这部分比代码更值得学）

| 测试 | 验证的关键行为 |
|---|---|
| `test_validation_error_is_not_retried` | 参数错误 → **尝试次数 0**（工具函数从未被调用） |
| `test_retries_until_success` | 退避序列精确等于 `[0.1, 0.2]` |
| `test_non_retryable_exception_stops_immediately` | `ValueError` → 只尝试 1 次 |
| `test_non_idempotent_tool_never_retries` | 非幂等 → 只尝试 1 次 |
| `test_circuit_records_one_failure_per_logical_call` | **反向案例**：一次调用重试 3 次也只记 1 次失败 |
| `test_opens_then_recovers` | 注入时钟，验证完整三态迁移 |
| `test_result_preview_is_also_redacted` | 返回值脱敏（我写示例时发现的真实 bug） |
| `test_jsonl_file_output` | 落盘内容确实脱敏过 |

**两个反面案例最值钱**：
`test_non_retryable_exception_stops_immediately` 防的是"重试过度"，
`test_circuit_records_one_failure_per_logical_call` 防的是"阈值形同虚设"。
正向案例只能证明功能存在，反向案例才能防住回归。

## 9. 建议的动手练习

1. **加幂等键**：给 `ToolPolicy` 加 `idempotency_key_arg`，
   让非幂等工具在带幂等键时也能安全重试。这是本库最大的局限。
2. **加异步版本**：用 `asyncio.wait_for` 实现真正可取消的超时。
3. **加跨进程熔断**：把 `CircuitBreaker` 的状态抽成接口，实现一个 Redis 版本。
4. **加 jitter 的 full-jitter 模式**：目前是 ±jitter，业界还有 `random(0, delay)` 的 full jitter。
5. **把审计接到 OpenTelemetry**：现在只能写 JSONL，接上 OTel 就能进 Grafana。
6. **写一个 benchmark**：对比"有重试/无重试"在同样失败率下的端到端成功率。

做完 1 和 2，你对"生产级工具层"的理解会超过大多数只写过 demo 的人。
